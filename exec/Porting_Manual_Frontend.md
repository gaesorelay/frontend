# 포팅 매뉴얼 (Frontend)

## 1. 프로젝트 개요
- **프로젝트명**: 개소릴레이 (Gaeso Relay) - Frontend
- **서비스 설명**: 실시간 다중 사용자 스토리 릴레이 게임 웹 클라이언트

## 2. 개발 환경
| 항목 | 내용 | 비고 |
| --- | --- | --- |
| **OS** | Windows 10/11 | Local 개발 환경 |
| **Language** | TypeScript | Node.js v18 이상 권장 (v24.13.0 Tested) |
| **Framework** | React v19, Vite v7 | Frontend Framework |
| **IDE** | Visual Studio Code | |

## 3. 빌드 및 실행 방법

### 3.1 사전 준비 사항
- **Node.js**: v18 이상 설치 (v24.13.0 권장)

### 3.2 프로젝트 빌드
터미널에서 프로젝트 루트 경로(`frontend`)로 이동 후 아래 명령어 실행

```bash
# 1. 의존성 패키지 설치
npm install

# 2. 프로젝트 빌드 (dist 폴더 생성)
npm run build
```

### 3.3 프로젝트 실행

**개발 모드 (Hot-reload 지원)**
```bash
npm run dev
```
- 실행 후 `http://localhost:5173` 접속

**배포 모드 (Nginx 등 웹 서버 필요)**
- 웹 서버(Nginx, Apache 등)의 루트 디렉토리를 빌드된 `dist` 폴더로 설정
- **SPA 라우팅 설정 필수**: 모든 요청(`/*`)을 `index.html`로 리다이렉트

## 4. 환경 변수 설정 (.env)
프로젝트 루트 디렉토리에 `.env` 파일을 생성하고 아래 내용을 설정해야 합니다.

| 변수명 | 설명 | 예시 값 |
| --- | --- | --- |
| `VITE_API_URL` | 백엔드 API 서버 주소 | `https://gsrelay.o-r.kr/api` |
| `VITE_SOCKET_URL` | 백엔드 소켓 서버 주소 | `wss://gsrelay.o-r.kr` |

## 5. DB 덤프 파일
본 프로젝트는 **Frontend** 애플리케이션으로, 별도의 데이터베이스를 보유하지 않습니다.

## 6. 시연 시나리오
| 시나리오 | 화면 | 내용 |
| --- | --- | --- |

| **로비 진입** |![](https://velog.velcdn.com/images/zhy2on/post/db5fccd3-945e-4b8d-af73-bfc4891d3c25/image.png) | 닉네임 설정 후 로비 입장 (배경음악 재생 확인) |

* 발표자는 서비스 메인 화면에 접속한다.
  메인 화면의 전반적인 UI 구성과 분위기를 간단히 설명한 뒤,
  **‘방 만들기’ 버튼을 클릭**하여 새로운 게임 방을 생성한다.

* 방 생성 화면에서 기본 설정을 완료한 후 방을 생성한다.
  생성된 **방 코드(또는 링크)**를 화면에 보여주며,
  관객들에게 “참여하고 싶은 분들은 자유롭게 접속해 달라”고 안내한다.

* 관객들이 차례로 로비에 입장한다.
  이때 **닉네임 설정 화면 → 로비 진입 과정**을 보여주며,
  로비에 입장했을 때 **배경 음악이 자연스럽게 재생되는지**를 함께 확인한다.

* 참여 인원 중 **이야기꾼 역할은 6:6으로 고정**한다.
  발표자는 팀 분배 과정을 설명하며,
  나머지 관객들은 **관전자(참여자)로 자유롭게 참여**할 수 있음을 안내한다.

* 모든 준비가 완료되면 발표자가 **게임 시작 버튼을 클릭**한다.
  게임이 시작되면서 화면 전환, 타이머, 카드 UI 등
  **전체적인 게임 UI 흐름**을 함께 보여준다.

* 게임 진행 중에는 다음 요소들을 중점적으로 시연한다.

  * 각 턴마다 이미지 카드가 제시되고, 이야기를 작성하는 흐름
  * **타이핑 UI와 제한 시간 동작**
  * 스토리 제출 시 발생하는 **효과음과 시각적 피드백**
  * 실시간으로 오가는 **채팅 기능**
  * 관전자들이 남길 수 있는 **반응(이모지/리액션) 기능**

* 모든 라운드가 종료되면 투표 단계로 넘어간다.
  관객 및 참여자들이 **각 팀의 결과물에 투표**하는 과정을 시연하며,
  투표 수 집계 및 결과 UI가 정상적으로 표시되는지 확인한다.

* 투표가 종료되면 **AI 심사위원 결과 화면**으로 전환된다.
  AI 심사위원이 각 팀의 이야기에 대해
  **점수와 코멘트를 제공하는 장면**을 보여주며,
  개소릴레이 서비스의 핵심 재미 요소임을 강조한다.

* 최종 결과 화면을 끝으로 게임을 마무리한다.
  게임이 종료되는 흐름과 함께
  “한 판을 처음부터 끝까지 함께 플레이했다”는 점을 정리하며 시연을 종료한다.
